## 已完成的事实调研结论

两个只读 subagent 已完成，无需重复同一轮调查。

### 推荐的书源底层路线

推荐 **B：Node Host 核心 + 独立 JVM/Rhino 高兼容 worker**：

- 保留现有基础规则引擎为 basic adapter，新增 JVM adapter。
- Host 独占 storageDomain、任务调度、网络/SSRF、秘密/Cookie、可见浏览器。
- worker 只接收不可变书源快照和 run 上下文，不直接访问数据库、秘密或任意网络。
- A「Node 单进程扩展」不适合执行不可信书源 JS；C「全部走 JVM 主引擎」迁移面最大，且仍不能自动解决网络、存储和任务问题。

关键代码证据：

- `/data/reader/index.js:28-31`：Host 直接创建 SourceEngine；`/data/reader/lib/source-engine.js:34-44`：引擎直接持有 fetchRemote。
- `/data/reader/lib/rules.js:29-35,47-70`：当前会拒绝 JS 并裁掉高兼容所需原始字段；需保存 raw、schemaVersion、engineKind。
- `/data/reader/lib/http.js:78-103,144-151`：SSRF/DNS/重定向防护可复用，应留在 Host broker。
- `/data/reader/index.js:31,46-65,286-329`：任务只有本机 Promise 与 running→queued，缺 lease、heartbeat、fencing、等待验证和跨进程取消。
- `/data/reader/index.js:54-65,347-365`：追更可能阻塞启动、串行拖延和重入。
- `/data/reader/index.js:215-226,295-329,379-385,446-460`：跨表逐条写，目录、下载、导入和恢复缺原子提交。
- `/data/reader/index.js:15-41`：公开 Remote 不应暴露内部 broker；worker RPC 需版本、runId/requestId、deadline、cancel、结构化错误和大小上限。

官方同路线是 **tsdown 构建 + `tsc --noEmit`**，可渐进迁移 TypeScript/TSX，但这是次级议题，不要用它替代底层架构讨论。

## 尚未拍板的决策

不要把这些当成用户已同意：

1. 书源引擎路线：混合 Host + worker / Node 单进程 / JVM 主引擎。
2. 演进方式：保留第一期数据和 Remote 的平滑演进，还是重写底层。
3. worker RPC、进程监督、资源限制与故障恢复协议。
4. Host capability broker 的授权、秘密句柄、Cookie 和审计边界。
5. 任务的 lease、heartbeat、fencing、重试、取消、`waiting_verification` 状态机。
6. 目录/下载/导入/恢复的事务或 staged generation 原子提交方案。
7. 公开 Remote 与内部 worker 协议的分离、版本和兼容策略。
8. JVM/worker 的打包、安装、健康检查、CI 和离线 fixtures/故障注入测试。
9. 是否以及何时渐进迁移 TS/TSX；只在底层结构确定后讨论。
